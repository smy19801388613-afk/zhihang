# 职航 · 实习与校招流程助手

本地单用户产品 v0.12.1，帮助整理真实经历、比较求职方向、制作专岗/通用/多岗简历，并记录申请进度。支持 DeepSeek 与兼容 Chat Completions 的模型服务。

## 下载与开始使用

- **普通用户**：[下载最新 Windows x64 分享包](https://github.com/smy19801388613-afk/zhihang/releases/latest)。在 Assets 中选择 `zhihang-版本-windows-x64.zip`，解压后双击「启动职航.cmd」。无需预装 Node.js/npm。
- **仅安装扩展**：同一发布页提供 `zhihang-capture-v版本.zip`，也可在职航的「浏览器扩展」界面下载。扩展需要在同一台电脑运行职航；安装后按页面步骤配对。
- **开发者**：可以下载本仓库源码或 `git clone https://github.com/smy19801388613-afk/zhihang.git`，按下方源码启动步骤操作。GitHub 自动生成的 Source code ZIP 不含运行环境和依赖。

首次启动为空白档案。可先体验演示模式；使用真实模型时，请在「模型设置」填写自己的 API Key。档案保存在自己电脑的 `data/`，模型请求会将所需材料发送至你选择的服务商。发布包不含开发者或其他用户的个人资料与凭证。

当前扩展支持 BOSS直聘实验采集，以及逐岗核对的字节校园网申实验渠道；网站结构可能变化，登录及验证码由用户自行处理。字节真实最终投递仍待验收，不承诺无人值守批量投递。Windows 分享包已在同机隔离环境测试；尚未在其他实体电脑验收。

## 打开方式

Windows 分享包解压后双击 **启动职航.cmd**，已内置 Node.js 和运行依赖；**停止职航.cmd** 关闭这份后台服务。源码开发版需要 Node.js 24 或更新版本，也可以执行：

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

默认地址：<http://127.0.0.1:4317>。关闭网页不会关闭后台服务。模型设置可直接在网页中验证并启用，无需重启。

## v0.12：通用简历、多岗位共用与字节网申接入

「岗位简历 → 简历用途」现在有专岗、通用和一份多岗三种模式。通用版直接根据已确认经历及求职方向生成，不要求先有公司或 JD；多岗版比较 2–8 个完整岗位 JD，合计最多 48,000 字符，提炼共同重点。原始 JD 不会为满足限额而被截断。通用和多岗简历有独立版本系列，应用设计规则、PDF 检查、网页编辑和对话修改均沿用原流程。

审核任一有效简历后，在「选择投递岗位」中复用同一版本。模拟渠道一次最多准备 20 个岗位，保存独立的岗位、城市和来源快照，共用同一个 PDF；批量填写与确认提交逐项保存，单项失败继续处理，提交结果不明则暂停该项，不能直接重试。已有专岗简历也能直接复用，不强制重新生成。

字节官网为独立的实验渠道：只接受 `https://jobs.bytedance.com/campus/position/{数字ID}/detail` 或对应 `/campus/resume/{数字ID}/apply`。BOSS 卡片不会被自动猜配成字节官网岗位。用户在「选择投递岗位」填写官方链接，审核选定简历并生成本次网申授权码，再在已登录的官网申请页点击扩展。采集配对码不能读取简历；网申授权码仅用一次、5 分钟过期，网申凭证绑定本次简历和岗位、60 分钟过期，可在投递记录撤销。

扩展对识别明确的空白字段提供填写计划，并可将同一审核 PDF 交给官网的附件控件。已有内容保留，学校自定义下拉、日期、未知字段和协议交给用户核对；不会把意向城市当成现居城市。官网还可能要求补充结构化经历，不能把“PDF 已交给上传控件”当成“上传解析或投递成功”。用户在扩展最终确认当前岗位、简历、剩余必填资料和协议后，只点击一次实测存在的“提交简历”；提交前保存记录，读不到可靠成功证据则保留待核验状态，不自动重试。这是逐岗确认的网申流程，不承诺无人值守批量投递。

真实网站验证与合成测试分开：公开岗位页面及登录跳转已读取；经登录页的无值结构诊断，姓名、手机号、邮箱、简历附件、专业和唯一“提交简历”按钮已识别。真实填写、上传完成及最终提交结果仍待验收，不能标记为实站投递通过。BOSS 岗位采集与本机模拟网申保持独立。

## 建议审核顺序

1. 在「模型设置」选择 DeepSeek，填写自己的 API Key，点击「验证并启用」。没有密钥时仍可审核明确标注的演示流程。
2. 在「我的经历」上传基础简历（含文字的 PDF、DOCX 或 TXT，最大 8 MB），核对自动填写的信息后确认导入。也可以使用虚构示例或原来的手动输入。
3. 确认经历事实；专业与意向岗位分别保存，不知道目标岗位可以留空。
4. 进入「方向与公司」，和助手交流兴趣、城市与优先项，比较“行业 × 岗位职能”。法学示例涵盖互联网数据合规、出海制造产品合规等方向。
5. 勾选感兴趣的方向，点击「发现公司与岗位」。每张卡片展示行业、公司、Logo（没有可用图片时用公司简称）、岗位、地点、薪资与 JD。右滑喜欢，左滑略过，也支持按钮和聚焦卡片后的方向键；可以撤销、回看略过的机会。喜欢清单和选择记录自动保存。
6. 在喜欢清单中打开「公司研究」，阅读公司业务、近期变化、岗位相关原文与来源日期。没有收录的公司可补充官网或官方新闻的 HTTPS 链接；没有证据的部分保持未知。
7. 点击「准备岗位简历」先进入该岗位的工作区，再点击「生成岗位简历」完成分析和生成。失败可在原工作区重试。尚无完整 JD 的卡片需先补充具体岗位原文，不用探索方向代替招聘要求。在「岗位简历」可以对话修改，或切换「网页编辑」直接调整文字、分区、顺序、模板和配色。实时预览与 PDF 使用相同版式。
8. 每次修改另存新版本，查看实际文字与版式差异、内部审核备注，重新审核后再准备模拟申请。不同公司的版本互不覆盖。
9. 让 Playwright 实际填写本机招聘表单、附加 PDF，核对截图后确认模拟提交；检查 `DEMO-` 回执。
10. 根据对应简历版本练习面试，刷新页面确认记录仍在。

如果已经有明确岗位，在「方向与公司」底部展开手动 JD 入口即可。

## v0.9：经历整理与岗位分析 agent

真实模型模式下，这两项流程改由 agent 主导语义理解，继续使用现有 DeepSeek 配置。规则演示模式单独标注，不把规则结果冒充 agent 判断。

- **经历整理**：读取完整经历原文，中性编号只用于定位，不预先判定经历边界。模型自己识别经历、角色、时间与父子项目，提炼可分别确认的事实，然后另一次请求从原文复核串段、层级、遗漏、否定和个人职责。每条事实保存精确原文引用、所属经历与待核对说明；不能确定的归属提出具体问题，不补造子项目。程序校验引用、原文覆盖、数字、关系结构与有限的范围约束，人工审核仍不可省略。
- **重新整理旧事实**：在「我的经历」点击「重新检查分段」也走 agent。先显示预览，确认替换后才将新事实写入，所有新事实都待确认。取消、模型失败或版本冲突不会替换旧确认记录；旧简历保留当时快照。新导入与手动「梳理经历」使用同一流程。
- **岗位理解与匹配**：第一步读取完整 JD，包括福利、公司介绍和末尾文字，自主概括岗位实质、关键任务和条件；第二步重新对照全文审查提炼结果，再结合已确认事实及个人字段判断。可修正第一步漏项或分类，分别展示硬门槛、能力、加分项与职责。程序不再用固定能力词表否决跨行业语义迁移。摘要与招聘引文分开，并说明直接经验、可迁移经验及其限制。未提供资料表示待确认，不能自动断言不具备。
- **行动建议**：分析页先展示核心工作、申请建议、相关优势、主要缺口与下一步，再展开每项条件与证据。建议不等于已具备能力或录用概率。薪资、城市和行业只接受可定位原文，保留薪资原币种与单位。旧分析仍可查看，生成新简历前会用新流程重新分析。
- **有限复核**：每个 agent 正常两次模型请求；结构或原文依据不合格时，仅允许额外一次修复，整个流程最多三次请求。关闭传输层嵌套格式重试，认证、限流、网络或超时不自动重试，不循环追问。仍不通过则不保存本次结果。模型服务调用有费用，较长材料可能比上一版耗时更多。

实现入口为 `server/experience-agent.ts`、`server/job-analysis-agent.ts`；测试包括原文覆盖、父子关系、跨岗位语义迁移、课程身份、未知与明确不满足的区分、引用和数字校验、隐私、有限请求次数及失败保留。界面继续复用事实确认、岗位分析与简历工作区。

已确认的经历类别也传给简历生成：企业工作/实习中的课程产品业务不会仅因出现“课程研究”就被当成课堂作业；个人课程项目仍需保留身份。简历生成会对省略身份的条目进行一次限定修正，仍需通过事实引用、数字和职责范围检查。

2026-10-06 使用本机 DeepSeek 完成 DOCX 导入的只读验证：经历与待确认事实的引用可定位，相邻经历保持分离。父子项目分组也做了独立验证，不编造未说明的其他子项目。具体输入与验证产物留在本机，不公开个人材料。测试结果没有写入个人档案，不自动确认事实。

北京丽兹行已导入 JD 与旧档案中 7 条已确认事实的真实链路也完成：分析 2 次、简历 2 次，得到 4 个章节、13 条内容，生产资料未变。学历门槛与 6 项职责分类正确，但模型仍将“经验不限＋培训带教”合为一项能力；此处属于分类质量限制，不能把整个语义验收称为完全通过。已进一步强调雇主提供的培训不是申请者能力，该提示修改后未重复付费实测。报告为 `test-results/job-analysis-resume-live-2026-10-06T11-46-51-233Z/report.json`，其中公开条件与私有资料统计分开保存。

“经验/学历不限”只有在引用和对应完整原文段均明确仅表示非限制时，才由程序归入带原文的「岗位补充说明」，并记录展示校正；裸“不限”及含真正资格的混合段不自动归类。公开网页的意义仍由模型理解，引用检查不能证明分类一定正确。自动化与界面验收使用合成资料及隔离数据库，和上述真实模型记录分开。

## v0.8 更新（历史记录）

- **事实分段**：按经历标题、日期、项目和职责段落划分，保留同一经历的标题上下文，不再按固定字数把相邻经历拼在一起。旧事实不会自动改写。在「我的经历 → 把事实确认下来 → 重新检查分段」先看预览，选择「确认替换，重新审核」才替换，新事实全部回到待确认；历史简历快照保留。
- **方向对话**：流程为「了解偏好 → 比较方向 → 确认并找岗位」，最多三轮收集偏好，之后收束到明确的下一步。已有候选方向时可随时点击「结束探索，进入下一步」，也可以继续问具体问题。避免反复介绍背景、重复追问同一主题。清空聊天会重置这段对话与方向，保留已保存岗位、喜欢清单、个人事实和历史简历。切换搜索方向也保留已喜欢的公司；个人档案变化仍须重新评估方向。
- **公开信息检索**：涉及公司动态时读取官网并进行一次有界公开搜索，最多打开三个搜索结果页；显示原文来源、正文/摘要标记、获取时间和可确认的发布日期。搜索只发送公开公司/行业关键词，不能取得材料时明确说明，官网介绍不能替代真实在招 JD。搜索结果受网络和网页结构影响，不保证全面或始终可用。
- **聊天附件**：每轮最多三个附件，单个最大 8 MB。PDF、DOCX、TXT 在本机提取文字；当前 DeepSeek 官方 `deepseek-flash` 原生接收 PNG/JPEG/WebP 静态图片，已完成真实图片识别测试（见 [DeepSeek 图片输入文档](https://api-docs.deepseek.com/guides/vision/)）。其他模型若未配置图片能力会明确拒绝图片，不伪装成已读图。待发送文件只在内存保留 30 分钟，发送成功、移除、清空或重启后释放；已发送文档文字随聊天保存，图片历史只保存名称，不保存原图。附件是参考材料，不会直接改成已确认个人事实。扫描 PDF 仍无 OCR，可改传页面截图。模型密钥留在本机后端。
- **公司目录覆盖**：不支持的行业不会再抛出整页错误，而是显示来源覆盖情况，保留已有岗位并允许通过扩展或手动 JD 继续。目录不足与用户经历是否适合无关，也不表示行业没有招聘。
- **岗位分析**：先由模型筛选并归类招聘原文，再匹配已确认事实。区分硬门槛、工作能力、加分项和职责，移除宣传、福利等内容；每项可查看招聘引文及个人证据，不再把所有句子当成必须条件。模型引文必须能定位到给定原文，不支持无依据新增或偷偷裁掉限定条件；旧分析在生成新简历前会重新分析。
- **简历范围校验**：课程身份只约束对应的课程项目，不会因相邻经历出现“课程”就给校园活动强加课程身份。若模型仍遗漏真实身份，只允许自动修正或删除失败条目一次，其他条目、日期、数字和事实引用不得改变；修正后重新执行全部校验，失败仍拒绝保存。正常匹配与生成共三次模型请求，此类修正至多增加一次业务请求，JSON 格式修复为独立机制。简历仍需人工审核。

当前和历史文档每轮合计最多送入模型 18,000 字符，当前附件优先，其次是最近历史文件；重复全文去重。超出部分明确标注只读到开头，不能据此声称看过全文。历史消息不再重复附带所有文件全文，旧图片需要重新上传才能再看原图。

## 浏览器扩展导入岗位

可加载目录：`extensions/zhihang-capture/`。这是 Chrome / Edge Manifest V3 扩展，在日常浏览器中使用；不需要启动专用采集窗口。BOSS直聘为**实验适配**，合成页面测试与真实登录页面验收分开记录；在真实验收完成前不承诺页面适配成功。

1. Chrome 打开 `chrome://extensions`，或 Edge 打开 `edge://extensions`，开启开发者模式，加载上面的已解压扩展目录，并固定到工具栏。
2. 打开职航的「浏览器扩展」页面，生成一次性配对码。在扩展预览页输入配对码完成连接。服务地址固定为 `http://127.0.0.1:4317`，配对码 5 分钟有效；重新生成会使旧码失效。
3. 自行登录招聘网站、筛选岗位，再点击工具栏的「导入职航」。扩展只读取本次页面的岗位区域，详情页读取当前岗位，列表读取最多 20 个已展示岗位；不翻页、不后台持续读取。
4. 独立预览页里勾选岗位、核对并修正字段，再确认导入。缺少完整 JD 的列表卡始终标为「详情待补充」；打开详情再次采集或手动粘贴完整 JD 后，才能分析和生成简历。登录、验证码或访问限制请在原网站自行处理。
5. 返回职航「浏览器扩展 → 我导入的岗位」查看原文、来源时间和修正记录，进入现有滑卡、喜欢清单、公司研究及岗位简历流程。切换方向、刷新官网/JobSpy 或重启不会移除这些导入记录。
6. 可在职航或扩展中断开连接。凭证仅限岗位导入，30 天后过期；断开不会删除已保存岗位。

扩展只申请 `activeTab`、`scripting`、`storage` 和固定本机地址权限，不申请所有网站、Cookie、聊天、历史、网络监听或调试权限。模型密钥不进入扩展，本版结构化提取不调用模型。专用 `/extension/v1` 接口采用来源绑定、哈希保存的可撤销凭证、严格字段与大小校验，单次最多 20 条、512 KB；不会返回工作区内容，也不会放宽 `/api` 的同源限制。导入冲突可保留预览重试，同一请求编号不会重复写入。

原始抓取与用户修订分别保存，已有手动修正受保护；再次采集可补缺，不静默覆盖修正。按平台岗位 ID 与城市区分岗位，工资保持原文。来源类型为 `browser_capture`，不标为官方核验或承诺持续在招。本轮不联系招聘者、不发送消息、不上传简历或投递申请；原有本机模拟网申仍可使用。

完整安装和故障说明见 `extensions/zhihang-capture/README.md`。可复验：`npm run test:capture-api`、`npm run test:capture-ui`；两者使用隔离数据，不改个人资料或真实招聘网站。

## v0.5 的四项改进

1. **岗位匹配与证据**：分开必要条件、优先条件和岗位职责，行业、地点、薪资单列为岗位信息。学历、专业、毕业时间、到岗安排可以引用个人档案字段；经历判断引用已确认事实。界面区分「信息待确认」与「明确不满足」，可展开核对字段和原文；不提供录用概率或未经验证的匹配百分比。
2. **简历成品与修改审核**：缺口与待核对事项保存在内部审核备注，不进入打印简历。新旧版本按真实内容比较，展示新增、删除、改写及版式变化；没有变化会明确显示，修改说明不能代替实际差异。网页编辑和对话修改继续分别保存版本，简历中的经历与数字仍需用户审核。
3. **扩大岗位来源**：保留腾讯、网易官网适配器，通过独立 Python 环境接入 MIT 许可的 JobSpy。LinkedIn、Indeed 的公开结果需经过城市、学生类型、具体岗位方向检查；官网重复岗位优先保留，同时为新增来源预留展示位置。安装、查询预算与失败状态见下文。
4. **公司研究**：在喜欢清单中读取公开公司网页和已取得的 JD，整理业务、近期变化、岗位重点与准备问题。每条重点附原文引文、链接、发布日期（若能确认）和获取日期；不能在材料中定位的模型引文会被剔除。不知道的内容留空，未知公司可补充最多 3 个 HTTPS 来源链接。相同输入的已保存研究可复用 24 小时，也可主动更新；研究材料与个人简历分别保存。

## 目前实现与边界

- 已实现本地 SQLite 保存、基础简历导入及字段对应、事实确认、职业探索对话、行业与岗位区分、多来源公开岗位获取、岗位滑卡及喜欢清单、带证据的岗位分析、公司研究、简历双途径编辑与版本差异、PDF 导出、模拟招聘站浏览器操作、结果核验与文字面试。
- 无模型密钥时是**规则演示模式**，不是实际大模型效果。规则输出会明确标注，不会伪装真实推理。
- 真实模型接口采用兼容 Chat Completions 的 HTTP 调用。DeepSeek 为默认预设，同时支持百炼和自定义地址。探针成功后保存并立即启用，失败保留原配置；已有工作区内容不因此改写。
- 真实模式下，首次简历生成会组织章节、筛选岗位相关经历并润色表达。条目必须引用已确认事实，数字按所引事实检查；固定教育与联系信息由本机模板输出。机械校验不能证明全部语义真实性，每一版都需用户审核。演示模式仍只选择和排列原文。
- 每版新简历显示生成来源；启用真实模型不会把旧演示版本伪装成模型生成。切换配置时正在执行的业务会阻止切换，以免同一任务混用两个模型。
- 演示模式支持常见简历修改指令：经典/现代模板、配色、精简措辞、明确的引号文字替换、摘要修改、经历章节重排。更自由的自然语言修改需要配置真实模型；无法理解时明确说明没有修改。
- PDF 目前支持文字提取，不含 OCR；扫描件、加密文件或旧版 `.doc` 请先转换。原文保留用于核对，无法识别的字段留空，不补造。
- 公司探索保留有限的官方招聘入口目录；腾讯校园招聘、网易实习岗位和安装后启用的 JobSpy 来源可查询公开岗位。来源可用性与覆盖随网站变化，完整范围、缓存与扫描限制见下文「岗位来源」。
- 公司研究在没有模型时仍会读取真实公开网页并明确展示原文摘录；模型整理失败会保留材料与失败说明。它不是完整商业尽调：不确认团队体验、持续招聘或薪资，面试问题也不代表已证明的公司事实。网页无可确认的发布日期时，不把获取日期当成近期新闻日期。
- 刷新岗位保留已保存的选择；本次未重新获取的喜欢职位保留历史 JD 和原获取日期，标记需要重新核验。每个具体职位绑定自己的简历，同一公司同名但不同城市的职位可分别准备；用户手动补充的 JD 优先保留。
- 模拟网申只操作本机自建测试站，其回执明确标为模拟。字节校招的真实浏览器网申另行授权，当前实站验证范围见 v0.12 说明。BOSS 暂不提供投递；右滑喜欢只保存选择，不提交申请。
- 本地单用户原型只监听 `127.0.0.1`。没有生产账号系统，不可直接改为公网服务使用真实个人资料。公网部署、用户隔离及真实渠道接入属于下一阶段。
- 浏览器优先使用已安装 Chromium，找不到时尝试 Edge/Chrome。都没有时运行 `npx playwright install chromium`。

## 简历设计与我的 Skills（v0.11）

在「岗位简历」中打开设计面板，选择「清晰通用」「紧凑一页」或「经典正式」，写下自然语言要求，或读取 `.md` / `.txt` 文件（包括 `SKILL.md`）。上限 12,000 字符；仅按文本解析，不安装技能、不执行脚本、不下载链接内资源。已有 DeepSeek 配置用于解析自由文本；无密钥时使用有限规则，并明确显示「规则演示」。

1. **解析并核对**：面板展示实际参数、已识别要求和不支持要求。解析预览不会自动修改简历。
2. **保存与选择**：保存给当前岗位使用，或设为新岗位的默认规范。最多保存 30 份；切换岗位时恢复默认选择。
3. **生成或应用**：新简历使用选中的设计；已有简历可只应用样式并生成新版本，正文、事实引用与原版本保留。

支持两种结构主题、四种强调色、无衬线/衬线字体、10–12 磅正文、1.35–1.8 行高、12–22 毫米页边距、栏目与条目间距、教育背景前置/后置、标题分隔线以及自动/一页/两页目标。任意 HTML/CSS、脚本、外部字体、照片、多栏和像素级自由布局暂未开放。首版没有自动联网搜寻或安装第三方 Skills。

每个简历版本保存设计规范快照及实际参数。删除规则库中的规范不改写历史简历；网页编辑及对话改写保留未要求调整的样式。匹配分析会传入初稿生成，但岗位要求和设计规则不能作为新增个人经历的依据。

生成、网页保存、对话修改或应用设计时，用 Chromium 生成实际 PDF，检查页数、文字完整性和溢出；如超过页数目标，最多一次收紧合法间距，保留全文。仍超过目标会显示警告，不靠删除内容或小于最小字号来压页。检测到文字丢失或溢出则不保存该版本；浏览器不可用时明确标为未检查。机械检查不代表排版美感或全部语义真实性，导出后仍需人工阅读。无设计参数的历史版本使用原模板。

验证入口：`npm run test:design-api`（隔离 HTTP、SQLite 与真实 PDF）；`npm run test:appearance`（历史样式回归）。实际模型联调需显式运行 `npx tsx scripts/check-live-design.ts --run`，只使用虚构资料，可能产生 API 费用，不修改用户工作区或模型设置。

## 岗位来源

目前组合两个自建官网只读适配器和单独安装的 JobSpy，无需招聘账号或模型密钥：

- **[腾讯校园招聘](https://join.qq.com/)**：官网公开的 `POST /api/v1/position/searchPosition` 查询岗位，`GET /api/v1/jobDetails/getJobDetailsByPostId` 核验完整职责和要求。仅保留应届、校招、实习类型，详情编号不符或详情缺失时不生成真实岗位卡。
- **[网易招聘](https://hr.163.com/job-list.html)**：官网公开的 `POST /api/hr163/position/queryPage`，使用官网当前的 `keyword`、`currentPage`、`workType=1` 参数，仅接入实习列表。即使来源忽略筛选，也会再次排除社招记录。校招项目若另有投递入口，以 JD 原文为准。
- **[JobSpy](https://github.com/speedyapply/JobSpy)**：使用 `python-jobspy==1.2.0`，通过本机 Python 子进程查询 LinkedIn 和 Indeed 的公开岗位。仅启用这两个来源，没有登录、提交申请或调用模型。上游包独立安装，不修改包源码；许可保留在 `THIRD_PARTY_NOTICES.txt`。

查询只发送岗位关键词、城市和固定的分页/类型参数，姓名、邮箱、简历和经历不发送给招聘网站。城市、岗位类型和职位匹配在本机再次过滤；当前是明确岗位职能规则，不是完整语义推荐。隐私合规、制造业产品合规还需 JD 含对应线索，不将所有法务岗位都视为同一方向。只保留有完整 JD 和公开来源链接的附加岗位。薪资缺失显示「未披露」；JobSpy 返回的金额、币种和单位按原始字段展示，并明确标记待核验，不将可疑的日/月口径自行换算。公司 Logo 使用已核验的官方 HTTPS 资源，未知公司或资源不可用时使用文字标识。

官网查询每家公司一次最多 2 个关键词，每个关键词仅扫描首页 30 条；优先给每个方向一个关键词，余量再查同义词。腾讯详情最多核验 10 个，网易最多返回 20 个。官网单请求最长 6 秒，整组官网查询最长 25 秒，请求间隔至少 300 毫秒，成功响应在内存缓存 5 分钟。

JobSpy 在官网查询同时运行，先把至多 3 个已选方向与城市规范化为英文查询，最多发送 6 个查询，每个只取首批最多 5 条结果；优先覆盖 LinkedIn 的方向/城市组合，预算有余量时查询 Indeed。桥接进程最长 45 秒，每个进程最多同时执行 2 个查询，最多同时运行 2 个搜索进程；单查询限制一次搜索页及最多 8 次请求，不翻页或重试。成功完成的查询缓存最多 5 分钟，缓存保留原获取时间。跨来源去重优先使用官网记录，合并后最多 40 张真实岗位卡，为附加来源预留最多 12 个位置。

「公开招聘职位」表示获取时对应来源返回该职位，不保证投递时仍开放；卡片同时显示具体来源。无匹配结果、连接失败、部分查询超时、详情核验失败、未安装 JobSpy 和未接入公司分别显示说明；完成的有效结果可以保留。其它公司的探索卡片保留官网入口。不以旧快照、模型生成职位或估算薪资补充真实列表；不绕过登录、验证码或网站拒绝访问，不自动提交真实申请。JobSpy 尊重本机现有系统代理设置，不创建或轮换代理，不读取浏览器登录会话。

两个官网适配器的端点、筛选参数、详情链接与官方 Logo 于 2026-10-03 实际请求核验。JobSpy 于 2026-10-05 做了有界公开查询，合规、产品、算法方向与上海、杭州组合检查 25 条后保留 5 条，部分来源请求受限；这是小样本运行记录，不代表完整岗位覆盖或长期成功率。实现位于 `server/job-discovery.ts`、`server/jobspy.ts` 和 `scripts/jobspy-bridge.py`，单元测试位于 `tests/job-discovery.test.ts`、`tests/jobspy.test.ts`。公开源实测记录在 `test-results/jobspy-live.json` 与 `test-results/jobspy-two-sources-live.json`，没有个人简历或密钥。

### 安装 JobSpy

需要 Python 3.10 或更新版本，依赖与 Node.js 主应用隔离。Windows 在项目目录执行：

```powershell
./scripts/setup-jobspy.ps1
# 如需指定 Python：
./scripts/setup-jobspy.ps1 -Python 'C:/Path/To/python.exe'
```

Linux/macOS 可运行 `sh scripts/setup-jobspy.sh`，也可先设置 `PYTHON` 指向解释器。安装器创建项目内 `.venv-jobspy/`，服务默认使用这个环境。另一已安装 JobSpy 的环境可通过 `.env` 中的 `JOBSPY_PYTHON` 指向其 Python 可执行文件。环境配置修改后重启服务。

`JOBSPY_ENABLED=false` 只关闭 JobSpy，腾讯和网易官网继续可用；`JOB_DISCOVERY_ENABLED=false` 关闭全部外部岗位获取。未安装 Python/JobSpy 时主应用仍可启动，来源面板给出安装说明。可运行 `npx tsx scripts/check-jobspy.ts` 进行一次有界公开源实测；它不使用模型、简历或申请操作。

## 接入真实模型

推荐直接使用网页中的「模型设置」：

1. 在 [DeepSeek 控制台](https://platform.deepseek.com/) 获取可用密钥，确认账户有余额与模型权限。
2. 选择 DeepSeek。预设基础地址 `https://api.deepseek.com`、模型 `deepseek-flash`、JSON 输出、90 秒超时。型号也可手动输入。
3. 将密钥填入本机密码输入框，点击「验证并启用」。程序发送固定 JSON 探针验证连接；成功后持久保存并启用。单独点击「测试连接」只测试、不保存。
4. 返回工作流程，导入真实简历或使用虚构测试资料评估效果。API 调用费用由服务商计费。连接通过只代表接口和 JSON 响应可用，不代表已评测所有职业建议与简历质量。

预设依据 [DeepSeek 官方接入文档](https://api-docs.deepseek.com/) 和 [Chat Completions 参数说明](https://api-docs.deepseek.com/api/create-chat-completion/) 核对。官方 DeepSeek 的预设型号采用非思考模式，普通任务输出上限 8192 tokens；经历/岗位 agent 在官方 deepseek-flash 或 deepseek-v4-pro 上使用 65536 tokens 上限，容纳完整原文引用，实际用量取决于返回内容。其他兼容服务保持 8192 上限，不收到 DeepSeek 专有参数。单次请求超时范围为 10–180 秒；长材料超时或截断时明确失败，不删除后半段材料来凑成功。

验证失败会区分密钥、权限、余额、限流、网络、超时和格式问题，不会自动切回演示。普通任务仅当内容的 JSON 语法或结构不符时，最多追加一次格式修复请求，可能产生一次额外调用费用；两次请求共用原时限。经历/岗位 agent 由业务层统一管理两阶段加一次修复，不叠加传输层重试。HTTP、余额、限流、网络、超时和截断错误不自动重试。修复仍失败或事实校验不通过时，不保存该次业务结果。更换服务商或 API 地址必须重新提供密钥，避免把原密钥发往新地址；不跟随 API 重定向。

仍支持传统 `.env` 配置：复制 `.env.example` 为 `.env` 后同时填写三项，再重启服务。

```dotenv
MODEL_API_KEY=你的密钥
MODEL_BASE_URL=https://api.deepseek.com
MODEL_NAME=deepseek-flash
MODEL_JSON_MODE=true
MODEL_TIMEOUT_MS=90000
PORT=4317
```

程序会追加 `/chat/completions`，也接受已经完整的接口地址；使用服务商提供的 HTTPS 地址，本机兼容服务可用 HTTP。网页保存的设置优先于环境变量；在网页明确切回演示后，重启也不会再次启用环境变量中的模型配置。

保存的密钥不通过读取接口返回，不写入日志或浏览器存储。Windows 上，网页保存的密钥使用当前用户的 DPAPI 加密，不能直接迁移给另一系统账户；其他系统使用权限为 0600 的本机配置文件。自行填写的 `.env` 仍是普通文本。经历与岗位文本会在真实模式下发送给所选服务商，流程尽量移除不必要的联系方式；用户自己写进自由文本的其他个人信息也可能随任务发送。不要把密钥粘贴到聊天或提交到版本库。
